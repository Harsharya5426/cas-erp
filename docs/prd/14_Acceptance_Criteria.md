# Acceptance Criteria and Definition of Done

## Global definition of done
- Approved requirement and acceptance criteria mapped to implementation.
- UI, API, database and permissions implemented end-to-end.
- Input validation and meaningful error handling.
- Unit/integration/E2E tests added and passing.
- Audit logging for sensitive actions.
- Accessibility and responsive checks completed.
- Security scans pass within agreed thresholds.
- Operational metrics, logs and alerts configured.
- User/admin documentation and support runbook updated.
- No placeholder controls or fabricated success messages.

## Critical end-to-end journeys
1. Applicant submits and tracks an application.
2. Authorized staff verify and approve admission.
3. Cashfree payment is verified server-to-server and reconciled.
4. Student enrollment and portal activation.
5. Faculty marks lecture attendance; correction is approved and audited.
6. Student/parent sees only authorized attendance and fee data.
7. Faculty submits marks; controller verifies; authorized role publishes.
8. Employee applies for leave; configured approvers act; attendance updates.
9. Accountant issues receipt and posts/reconciles ledger entry.
10. Student requests certificate; verification and authorized signing complete.
11. Grievance is assigned with confidentiality preserved.
12. Backup is restored into a test environment and validated.

## Pilot exit criteria
- Critical user journeys pass.
- No unresolved critical security defects.
- High-severity issues have approved remediation plans.
- Migration reconciliation signed off for pilot data.
- Support, training, escalation and rollback tested.
- Pilot users approve usability and process fit.
- Institution formally authorizes next rollout phase.
